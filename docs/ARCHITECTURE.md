# Как устроен сайт

Коротко: React + TypeScript, собирается Vite в статику, работает на GitHub Pages
и одинаково хорошо ляжет на любой другой сервер. Бэкенда своего нет — его роль
играет Supabase, и заменить его можно, не трогая интерфейс.

## Раскладка по папкам

```
src/
  data/        схема данных, хранилище состояния, профиль (Саша / Соня)
  storage/     адаптеры хранилищ — единственное место, знающее про бэкенд
  features/    экраны: вишлисты, моменты, планы, статистика, настройки
  components/  мелочь общего пользования
  lib/         роутер
  styles/      токены оформления и стили экранов
supabase/      SQL-схема базы
```

## Главное решение: слой хранилища

Ни один экран не знает, где лежат данные. Все разговаривают с интерфейсом
`StorageAdapter` ([src/storage/types.ts](../src/storage/types.ts)):

```ts
list(collection)            // прочитать коллекцию
upsert(collection, row)     // добавить или обновить запись
remove(collection, id)      // удалить
subscribe(collection, cb)   // узнать о чужих правках
putMedia / getMediaUrl      // картинки
exportAll / importAll       // выгрузка и загрузка целиком
```

Реализация пока одна — `SupabaseAdapter`: записи в Postgres, картинки в Storage,
вход по email.

Был ещё и локальный адаптер, хранивший всё в браузере, но его убрали намеренно.
Сайт для двоих, а локальные данные означают, что у каждого свой отдельный архив:
один добавляет желание, второй его не видит и решает, что сайт сломан. Один
способ хранения, зато честный. Слой абстракции при этом остался — он нужен не
для выбора между «браузером и облаком», а для переезда на свой сервер.

Интерфейс намеренно построен вокруг коллекций, а не вокруг «одного большого
JSON-файла». Файловый вариант проще, но при нём двое, редактируя списки
одновременно, затирают правки друг другу: кто сохранил последним, тот и прав.
С отдельными записями такой проблемы нет.

## Переезд на свой сервер

Заложено два пути; выбирать можно будет тогда, когда сервер появится.

**Путь 1: перевезти Supabase целиком.** Он открытый и ставится через
`docker compose`. Меняется только `VITE_SUPABASE_URL` — код не трогается вообще.
Самый дешёвый по усилиям вариант.

**Путь 2: написать свой API.** Тогда появляется второй адаптер, `ServerAdapter`:
те же десять методов, внутри `fetch` к твоему серверу. Всё остальное
приложение остаётся как есть — ему всё равно, кто на том конце. Тип `'server'`
для этого уже заведён в `StorageKind`.

В обоих случаях данные переносятся через **Настройки → Выгрузить JSON** и
обратной загрузкой.

## Схема данных

Вся форма данных описана в [src/data/schema.ts](../src/data/schema.ts) и
пронумерована через `SCHEMA_VERSION`. Любые прочитанные данные проходят через
`migrate()` — она приводит их к текущей версии и молча отбрасывает битые записи,
чтобы одна кривая строка не роняла весь сайт. Когда форма меняется, версия
растёт и в `migrate()` добавляется шаг: старые выгрузки должны открываться
всегда.

## Профиль и оформление

Выбор «Саша или Соня» — настройка устройства, а не общие данные: она лежит в
localStorage. Иначе переключение у одного меняло бы интерфейс у другого.

Профиль ставит `data-person` на корневой элемент, тема — `data-theme`. Всё
оформление построено на CSS-переменных, и компоненты не знают ни про людей, ни
про тему: они используют `var(--accent)` и выглядят правильно в любой из четырёх
комбинаций.

## Маршрутизация

Роутер свой, на хэше (`#/wishes`), ровно 30 строк. Хэш выбран не от бедности:
статический хостинг не умеет отдавать `index.html` на произвольный путь, и при
перезагрузке `/wishes` пользователь получил бы 404. С хэшем ссылки работают
одинаково и на GitHub Pages, и на своём сервере, без серверной конфигурации.

## Сюрприз в вишлистах

Когда один бронирует желание из чужого списка, владелец списка этого не видит:
статус `reserved` показывается ему как обычный `open`
([wishHelpers.ts](../src/features/wishlist/wishHelpers.ts)).

Прячет это интерфейс, а не база: обе половины пары технически могут достать
сырые строки через API. Защищаться тут не от кого — сюрприз держится на
договорённости, и этого достаточно.

## Что осознанно не сделано

- **Нет библиотеки роутинга и состояния.** Два человека и пять экранов — React
  Context и 30 строк роутера справляются, а обновлять нечего.
- **Нет работы без интернета.** Раз хранилище одно и оно в облаке, без сети сайт
  не откроется. Это цена отказа от локального режима, и она осознанная.
- **Картинки не сжимаются при загрузке.** Фотография с телефона улетит в облако
  как есть, на несколько мегабайт. Если упрёмся в лимит — добавим сжатие в
  `putMedia`, это одно место.
