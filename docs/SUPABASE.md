# Подключение облака

Все данные сайта живут в облаке: что сохранил один, сразу видит второй. Другого
хранилища нет, поэтому без этой настройки сайт не запустится. Времени — минут 15.

## 1. Завести проект

1. Зарегистрируйся на [supabase.com](https://supabase.com) (бесплатный тариф).
2. **New project**. Имя любое, регион — ближайший (Frankfurt), пароль к базе
   сохрани в менеджере паролей: он понадобится, если захочешь подключиться к
   базе напрямую.
3. Подожди пару минут, пока проект поднимется.

## 2. Создать таблицы

1. Открой **SQL Editor → New query**.
2. Вставь целиком содержимое [`supabase/schema.sql`](../supabase/schema.sql).
3. **Перед запуском** замени `sasha@example.com` и `sonya@example.com` на ваши
   настоящие адреса — доступ к данным получат только они.
4. **Run**.

Скрипт создаёт таблицы, включает разграничение доступа, включает живое
обновление и заводит закрытое хранилище для картинок.

## 3. Завести два аккаунта

Прямо на сайте: на экране входа поставь галочку «Это первый вход, создать
аккаунт», введи свой email и пароль. То же самое Соня делает у себя.

Адрес должен совпадать с тем, что вписан в `allowed_emails`, иначе вход
произойдёт, но данные не откроются.

При самом первом входе сайт один раз спросит: «Кто ты — Саша или Соня?». Ответ
закрепляется за аккаунтом, и больше вопрос не задаётся: переключателя личности в
интерфейсе нет, потому что от неё зависит, чей вишлист «мой» и кто кому готовит
подарок.

Если имя выбрали неверно, поправь его в SQL Editor:

```sql
update auth.users
set raw_user_meta_data = raw_user_meta_data || '{"person":"sonya"}'
where email = 'почта@example.com';
```

Тем же запросом можно назначить имя заранее, до первого входа — тогда вопрос
вообще не появится. Допустимые значения: `sasha` и `sonya`. После изменения
нужно выйти и войти снова, чтобы сайт увидел новое имя.

Если Supabase просит подтвердить адрес письмом, а письма не идут, отключи
подтверждение: **Authentication → Sign In / Providers → Email → Confirm email**.

Когда оба аккаунта созданы, лучше закрыть регистрацию совсем:
**Authentication → Sign In / Providers → Email → Allow new users to sign up** — выключить.
Белый список и так никого лишнего не пустит, но пусть будет два замка.

## 4. Прописать ключи в сайте

Нужны два значения, и лежат они в разных разделах:

- **Project URL** — вида `https://xxxx.supabase.co`.
  **Settings → Data API**, поле вверху страницы.
- **Publishable key** — начинается на `sb_publishable_…`.
  **Settings → API Keys**, вкладка «Publishable and secret API keys».

Оба сразу показывает и зелёная кнопка **Connect** вверху панели.

Ключ `sb_secret_…` с той же страницы в сайт вставлять нельзя: он обходит все
политики доступа и нужен только серверным программам. Вкладка «Legacy anon,
service_role» — прежний формат ключей, она не нужна.

Есть два способа их указать.

**Способ А, быстрый.** Ввести на экране первой настройки — он открывается сам,
если сайт запущен без ключей. Они сохранятся в браузере, но вводить придётся на
каждом устройстве, так что это вариант «поскорее посмотреть».

**Способ Б, правильный.** Положить в сборку:

- локально — создать файл `.env` по образцу `.env.example`;
- на GitHub — **Settings → Secrets and variables → Actions → New repository secret**.
  Там годится любой из двух вариантов: один секрет `SUPABASE`, в который целиком
  вставлено содержимое `.env` (обе строки сразу), или два отдельных —
  `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`. Сборка понимает оба.

Тогда сайт подключается к облаку сам, остаётся только войти.

## Почему publishable-ключ не секрет

Он попадает в собранный сайт, и это нормально: ключ лишь разрешает *попробовать*
обратиться к базе. Что именно разрешено — решает сама база (RLS-политики из
`schema.sql`), а они требуют вход с адресом из белого списка. Без этого ключ не
открывает ничего — потому Supabase и называет его publishable.

А вот **secret** ключ (`sb_secret_…`, раньше назывался service_role) — настоящий
секрет: он обходит все политики. В сайте он не нужен, и в репозиторий его класть
нельзя.

## Сколько это стоит

Бесплатного тарифа хватит с огромным запасом: 500 МБ базы и 1 ГБ файлов. Наши
списки — это килобайты; упереться можно только в фотографии, и то нескоро.

Одно «но»: проект на бесплатном тарифе засыпает после недели простоя. Пишет об
этом письмом, будится одной кнопкой. Если сайтом пользоваться хотя бы изредка,
этого не случится.
